**Maintainer: Ben Kay** (ben.kay@live.com.au · GitHub: bvkay)
Repo: `bvkay/AuScope_doi_tracker` · Site: https://bvkay.github.io/AuScope_doi_tracker/
Last updated: 2026-08-30 — **read §4 and §10 first: the `verified`/`candidate`

trusted.** Recent work: F-UJI FAIR scoring · MT deployment register · NCI

Tracks and publishes AuScope's research impact and infrastructure service
metrics. Everything is derived by automated pipelines from public APIs and
committed to git — no hand-entered numbers anywhere.

---

## 1. The one rule

**Every number on the site must be machine-derived, dated, and traceable to
a public source.** If a figure cannot be reproduced by re-running a script
against a citable service, it does not go on a page. Where data is missing,
we display the gap (see "unrecorded" / "not in API" / "keyword only") rather
than estimating silently. This is what makes the site defensible to a funder
or an audit, and it is the constraint that should survive every future
change.

## 3. The pipelines

### Weekly — `.github/workflows/monthly-search.yml`
Sundays 02:00 UTC, plus on push to `data/pending.json`,
`data/publications.json`, `data/review-decisions.json`,
`data/evidence-overrides.json` (i.e. the Google Sheet's send buttons).

Step order matters — each stage consumes the previous one's output:

1. **Process pending DOIs** (`process-pending.js`) — DOIs staff pasted into the sheet. Rejects dataset/instrument DOIs (see `config.excluded_doi_prefixes`).
2. **Full keyword search** (`search.js`) — 39 queries across OpenAlex, Semantic Scholar, Europe PMC. **Conditional**: runs only on the weekly schedule or a dispatch with `run_search: true` — the sheet-triggered pushes listed above skip it.
3. **Dataset inventory** (`dataset-inventory.js`) — EarthBank, AusPass, NCI MT/DAS. NCI records carry `subset: 'MT'|'DAS'` (which GeoNetwork tree they came from) — the per-subset hub cards depend on it.
4. **Maintenance** (`maintain.js`) — dedup + metadata fill.
5. **Review queue decisions** (`process-review-decisions.js`) — applies human accept/reject from the sheet.
6. **Verified discovery** (`verified.js`) — identifier evidence via OpenAlex (AuScope ROR, watchlist ORCIDs).
7. **Evidence ladder** (`evidence.js`) — merges identifier + text evidence into one `evidence` field per record; applies `evidence-overrides.json`.
8. **Same-work consolidation** (`consolidate.js`) — folds duplicate DOIs for one work; removes peer-review artifacts.
9. **AusMT run harvest** (`ausmt-inventory.js`) — see §5 below. Gated on the portal's `build.json` build_id: a 300-byte request when AusMT hasn't rebuilt; portal unreachable → keeps the existing snapshot, exits 0.
10. **Cross-pillar stats** (`stats.js`) — publications, datasets (by subset, with per-subset F-UJI averages joined by DOI), samples, stations, instruments, AusMT (live portal counts + run-register rollup), NVCL, AuSIS → `docs/stats-data.json` + dated snapshot in `data/stats-history.json`.
11. **Dashboard** (`dashboard.js`) — regenerates `index.html`, `widget.html`, `data.json`, `publications-data.json`.

### Weekly — `.github/workflows/nvcl-harvest.yml`
**Mondays 03:00 UTC** (300-minute ceiling), five steps:
THREDDS catalogue snapshot (`nvcl/thredds-catalog.js`) → **budgeted incremental
TSG enrichment** (`nvcl/tsg-enrich.js --max-new=300`, states WA,NT,TAS,SA,QLD,VIC
— both these steps are `continue-on-error`) → 8-node harvest (`nvcl/harvest.js`,
~50 min) → stats → dashboard. Commits the TSG cache and catalogue alongside the
usual outputs.

**Do not "correct" this to monthly.** It is weekly *because* TSG enrichment is
incremental and budgeted at ~300 new archives per run, so national coverage
accumulates over roughly four months of runs — and that tier supplies
**1,157.88 of the 1,737.65 headline unique km** (the API tier supplies 441.9).
Slowing the cadence stalls the backfill; the committed `data/nvcl/tsg-cache.jsonl`
is the durable asset that makes each next run cheap.

### Monthly — `.github/workflows/fair-assessment.yml`
1st of the month, 03:00 UTC, plus manual dispatch. Boots a pinned F-UJI
Docker container (`ghcr.io/pangaea-data-publisher/fuji:3.5.0`, ~60 s cold
start, health-polled on `/fuji/api/v1/ui/`), runs `src/fair-assess.js`, and
commits only `data/fair-scores.json` + `docs/fair-scores.json`. Monthly, not
weekly, deliberately: metadata changes slowly and F-UJI scores drift ±1–2 pts
between runs (live harvesting) — weekly re-scoring would publish noise.
**TODO after the first successful dispatch:** diff a few scores against the
committed baseline (assessed locally with pip v3.5.1) and pin the image by
`@sha256` digest.

**Secrets** (repo settings): `S2_API_KEY` (Semantic Scholar), optional
`CORE_API_KEY`, `DIMENSIONS_API_KEY`. Everything else is keyless — F-UJI's
`marvel`/`wonderwoman` Basic auth is the project's own published default,
fine for a localhost/CI container.

## 4. The evidence ladder (the core concept)

Every publication carries an `evidence` grade — best evidence wins:

| Grade | Meaning |
|---|---|
| `verified` | AuScope ROR or funder identifier on the paper (OpenAlex), **confirmed by raw affiliation text containing "AuScope"** |
| `candidate` | Watchlist ORCID + partner-institution co-affiliation |
| `text-attributed` | AuScope/facility acknowledgement found by text scan |
| `text-infrastructure` | Infrastructure-use wording |
| `text-software` | AuScope-supported software (GPlates, Underworld…) |
| `keyword` | Keyword match only — no confirmed signal, shown honestly |

> ✅ **Resolved 31 Aug 2026.** The top two tiers read 0 from 9–30 Aug — a live
> defect, not a true zero. Root cause confirmed as suspected: `fetchAllWorks`
> returned `[]` on a page-0 fetch error, indistinguishable from a real empty
> result, and the split-and-write block wrote it unconditionally; `evidence.js`
> then compounded it by dropping ROR-verified-only records (corpus 3,106 →
> 2,902). Fixed in `src/verified.js`: a failed fetch now sets a
> `fetchFailed` flag, and the writer **refuses to overwrite a non-empty
> verified file with an empty result** (exit 1, loud message;
> `VERIFIED_ALLOW_EMPTY=1` is the deliberate override). Re-running
> `npm run verified` + `npm run evidence` restored the ladder:
> **verified 47 · candidate 114 · corpus 2,921**, 19 ROR-verified works
> re-appended. If the tiers ever read 0 again, believe the guard, not the zero.

The hub displays the full split. **Showing the keyword-only count is the
point**: an auditable "here's what we can and can't prove" beats a single
unverifiable total. `data/evidence-overrides.json` is the human curation
valve (remove/regrade with a reason); `data/review-rejects.json` records
permanently rejected candidates.

## 5. The MT deployment register (station.json is the sole source)

**The decision (Ben, 25–26 Aug 2026):** MT instrument deployments are
accounted for ONLY from AusMT's per-station run records
(`https://ausmt.auscope.org.au/data/products/<survey>/<station>/station.json`
— the `/data` prefix is required). Each populated run carries a
second-precision `time_period` plus the recorder AND each magnetic coil by
model, serial and 10.82388 DOI — granularity DataCite cannot reach. The
instrument registry's 13 field-survey records (Coverage windows, HasPart
component lists) are **deliberately not used** for deployment numbers; they
remain as PID-graph links only. Corollary: **recording-days ≠ deployment-days**
— run-derived hours measure acquisition time (transport/setup/idle excluded),
never mix them with campaign-window figures in one total.

**The harvester** (`src/ausmt-inventory.js`, weekly step + `npm run ausmt`,
`--force` to ignore the build sentinel):
- Station list from `mtcat.json`; probes **three spread stations per survey**
  (first/middle/last) to classify runs as populated / scaffolded / none, then
  fully harvests populated surveys only.
- Tags every occupation `af: true|false` (AuScope-funded, via the registry's
  `fundingReferences` — two DataCite pages; fetch failure → `af: null` +
  `scope_tagged: false`, page falls back to raw totals with a loud notice,
  never zeros).
- Writes `data/ausmt-runs.json` (canonical) + `docs/ausmt-data.json` (page
  feed, includes a `stations` block of per-station lat/lon for the mini maps).

**Coverage today:** 1 of 27 surveys populated (NVP 2019 — **48 AuScope-funded**
instruments, **142 AuScope-funded** occupations, **285.0 AuScope-funded**
recording-days, peak 46 recording simultaneously). Raw totals in the same JSON
are 51 / 147 / 302.3 — the difference is the 3 GSSA-funded coils outside AuScope
scope, so check which pair of figures you are reading. 10 surveys are scaffolded
(runs structure, placeholder times, no instrument ids — the seven AusLAMP SA
surveys + Musgraves APY 2016 + NSW + Western Gawler 2023, i.e. the cheapest
upgrades); 16 have no runs.

**Do not quote AusMT's 2,625 stations as deployment evidence.** That is the
declared station count summed across all 27 surveys (what the portal holds);
run-level coverage is **49 stations, 1.9%** of it. The hub card is worded
honestly ("1 of 27 surveys populated") — keep any reuse of these numbers
equally explicit. **Multi-survey readiness was verified by
simulation** — tiles, chart title, compressed long-span axis, Surveys column,
per-survey rollups and two-state maps all adapt with zero code changes.

**To add a survey to the register:** (1) make sure its instruments exist in
the 10.82388 registry **with AuScope in `fundingReferences`** — instruments
missing that land in the "also served, outside AuScope totals" note; (2)
populate the survey's `runs` metadata in AusMT and rebuild the portal. The
weekly harvest sees the new build_id and everything downstream (feed, page,
hub card) updates itself. Note `instrument_pid` currently lives in AusMT's
portal-internal `surveys.json`, not the MTCAT contract — promoting it into
the coming `survey-metadata.json` contract is an AusMT-side (Ben) action.

## 6. The F-UJI FAIR scores

**What it is:** every assessable dataset DOI (datasets.json minus
PhysicalObject samples and empty DOIs — **168 on the current roster; 167 carry
scores** from the 25 Aug baseline, the inventory having gained a record later
that evening) gets an automated FAIR
assessment from a self-hosted [F-UJI](https://github.com/pangaea-data-publisher/fuji)
server, **pinned to metric set v0.8** (17 metrics, 26 points). Baseline
(25 Aug 2026, local pip v3.5.1): AusPass avg 55%, EarthBank 47%, NCI 43%;
corpus range 40–65%, median 52%.

**How to read the numbers (this matters when a funder quotes them):**
- v0.8 scores run structurally low — several metrics (e.g. FsF-F3-01M,
  data-file identifiers in metadata) fail on almost every real-world
  repository, so **35–60% is the normal band**, not an AuScope embarrassment.
  That is why the column thresholds are **≥60 good / ≥45 warn** — NOT the
  80/60 used for the DataCite-completeness columns.
- Scores are **not comparable across metric versions** (v0.5 = 16 metrics/24
  pts). The feed carries one `metric_version`; never mix versions in a
  display. Every page stamps version + assessment date.
- Scores largely measure the *hosting platform's* metadata exposure
  (DataCite record richness, landing-page markup) — 108 of 167 DOIs are
  hosted by third parties (EarthScope/IRIS, NCI). NCI's low average is an
  exposure gap, not poor curation: GeoNetwork's rich ISO 19115 metadata is
  invisible to F-UJI. Frame accordingly; per-metric breakdowns exist so the
  conversation can be about specific fixable gaps (licence metadata is the
  single biggest lever on AusPass and NCI records).
- Re-runs drift ±1–2 pts (live harvesting); `fair-assess.js` keeps the
  previous score when an assessment fails (max 3 attempts, `last_error`
  recorded) — the "citation counts only increase" philosophy applied to
  scores-on-failure.

**Plumbing:** `src/fair-assess.js` (`npm run fair`) posts each DOI to a local
F-UJI server (`FUJI_SERVER`, default `http://localhost:1071`) and no-ops if
none is running, so the step chain never breaks. Store =
`data/fair-scores.json` (keyed by normalised lowercase DOI); page feed =
`docs/fair-scores.json` (per-DOI `{s,f,a,i,r,m,p,t,d,checks[]}` + one shared
`metric_names` map). Pages join client-side via `normaliseDoi` and fail soft
if the feed is absent.

**Self-hosting facts (hard-won):** f-uji.net has **no public API** (UI only;
its About page redirects bulk use to self-hosting). **Never `pip install
fuji`** — that is an unrelated 2019 package; install from the GitHub tag
(`pip install "fuji @ git+https://github.com/pangaea-data-publisher/fuji.git@v3.5.1"`)
or use the Docker image (versioned tags stop at 3.5.0; `latest` tracks
unstable 4.0.0 master — pin, never `latest`). ~60 s cold start; the API
self-reports `software_version: 0.0.0` when pip-installed from a tag, so
provenance comes from the pinned version, not the response.

## 8. Key design decisions

- **Crossref excluded from discovery** — its fuzzy `query=` returns false positives. Metadata enrichment only.
- **Citation counts only increase** — protects against API inconsistencies.
- **Infrastructure DOIs are guarded out of the publications corpus** at three gates (search, pending, evidence append). OpenAlex indexes DataCite records as works, so registry/EarthBank/FDSN DOIs leak in otherwise (`config.excluded_doi_prefixes`).
- **OpenAlex mis-affiliates "Scope"-named orgs** (Healthscope, Scope Australia) onto AuScope's ROR entity — `verified.js` requires the raw affiliation string to contain "AuScope". Worth reporting upstream.
- **Same-work consolidation** keeps one record per work (published > preprint, non-versioned > .vN, Zenodo concept > version), folding other DOIs into `relatedDois`. Citations take the group **maximum**, never the sum.
- **NVCL scan metrics (merged-v1.2)** — see `src/nvcl/METHODOLOGY.md`, the citable counting-rules document (which also carries v1.3 "mirror-only measurement" and v1.4 "carry-forward" sections despite its v1.2 title — worth retitling at source). Headline figures now published: `unique_scanned_km` 1,737.65 · `total_scan_km` 1,751.01 · `mirror_only_km` 208.39 · `national_measured_km` 1,946.04 · `estimated_km` 4.22 · `combined_estimate_km` 1,950.26. Datasets with no published intervals go to an explicit unrecorded bucket (97 nationally — WA 69, NSW 20, QLD 4, NT 2, SA 2, TAS 1) plus a **disclosed** estimation tier, never silently blended. The two retired methods are described qualitatively in that document.
- **Map projection** — longitude scaled by cos(mid-latitude); viewBox 644×600, not 860×600 (which stretched Australia ~34%).
- **AuSIS is read, not rebuilt** — `AuScope/AuScope_Outreach` operates the network (hourly probes, waveforms, school dashboards); this repo accounts for its impact and links to it.
- **Station.json runs are the sole MT deployment source** (see §5) — registry field-survey records are PID-graph links only, and recording-days are never mixed with campaign-window days.
- **F-UJI thresholds are 60/45, not 80/60** (see §6) — metric v0.8 scores are structurally lower than completeness scores; reusing the mapping thresholds would paint the whole corpus red.
- **AuScope-funded scope via `fundingReferences`** — the registry holds partner-funded instruments too (16 Adelaide "Orange Box" receivers, 3 GSSA coils); every AuScope headline filters on the funding reference, and exclusions are disclosed, not hidden.
- **Surveys are hidden on instruments.html, not deleted** — still fetched for hierarchy and unit membership. The "Relations typed URL not DOI" fleet line was removed with them: its 13 carriers are all surveys, so a units-only count would falsely read 0 on a known registry gap.
- **The hub cards subsets, not aggregates** — one explorer card per dataset subset (EarthBank / AusPass / NCI MT / NCI DAS) with its own count and avg F-UJI; the "Impact at a Glance" tile band was removed as duplication (widget.html keeps its own band — that is its whole job); `datasets.html` demoted to an un-carded router.
- **Bot-commit merges**: the weekly Action commits generated files, so local work can race it (rejected push). Recipe: merge, keep **theirs** for `data/stats-history.json` (bot appended snapshots you lack), **ours** for source files and `data/datasets.json`, then re-run `stats.js` + `dashboard.js` to rebuild all generated docs from the merged data before pushing.

## 9. Runbook

```bash
npm run stats        # cross-pillar numbers → docs/stats-data.json
npm run dashboard    # regenerate hub + widget + feeds
npm run datasets     # rebuild data/datasets.json (EarthBank/AusPass/NCI)
npm run ausmt        # AusMT run harvest (add -- --force to ignore build sentinel)
npm run fair         # F-UJI scoring — needs a local F-UJI server on :1071 (no-ops without one)
npm run verified     # identifier evidence from OpenAlex (see the §4 warning first)
npm run evidence     # re-grade the evidence ladder
npm run consolidate  # fold duplicate works
npm run nvcl         # full NVCL harvest (~50 min, 8 nodes)
npm run nvcl-catalog # THREDDS catalogue snapshot (CI step 1 of the NVCL job)
npm run tsg-enrich   # incremental TSG enrichment — supplies ~2/3 of the NVCL km
npm run update-fdsn  # refresh the shared FDSN DOI table
```

`package.json` also carries `sync-from-sheet` / `sync-to-sheet`, which point at
a `src/sync.js` that **does not exist** (the full-sheet sync was retired, §7) —
delete both. `search`, `process-pending`, `maintain`, `review-decisions` and
`full-run` exist and do what their names say.

**Serving locally:** `cd docs && python3 -m http.server 8766`
(port 8765 is often occupied by an unrelated stale server).

**Testing the NVCL harvester safely:**
`NVCL_ONLY=TAS NVCL_OUT_DIR=/tmp/x node src/nvcl/harvest.js`
The health guard refuses to write if <5 nodes answer or boreholes drop below
80% of the previous snapshot — a degraded harvest can never shrink the
national numbers silently.

**Manual/diagnostic scripts** (not in CI): `check-partners.js` (audit partner
RORs), `harvest-orcids.js` (ORCID candidates), `scan-tiers.js` (text tier
scan — last run May 2026, worth refreshing), `compare.js`.

## 11. Downstream consumers (don't break these)

The published `docs/*.json` feeds are a public contract the moment they ship.
Known consumers:

  own headline tile band (that is its entire job; the hub's duplicate band was
  removed 26 Aug, the widget's must stay).

- **Rebecca Farrington's fork** — `rebeccafarrington.github.io/AuScope_doi_tracker/`
  (Aug 2026). **Not a passive mirror: it runs its own pipeline.** Verified
  30 Aug:
  - **Reuses six of our files byte-identically** (SHA-256 match):
    `fair-scores.json`, `ausmt-data.json`, `nvcl-data.json`,
    `australia-outline.json`, `fdsn-doi-data.js`, `tracker-chassis.js`. Her
    pages read `.scores` (DOI-keyed), `metric_names`, `fuji_version`, the
    `NCI MT` / `NCI DAS` subset keys, and every page loads our chassis — so
    **reshaping `fair-scores.json` or `tracker-chassis.js` upstream breaks her
    pages silently.** There is no version field, schema contract, or
    notification path between the two repos.
  - **Publishes four feeds that do not exist upstream** — `datasets-data.json`,
    `registry-enrichment.json`, `registry-licenses.json`, `software-data.json`
    — generated by code that lives only in her fork, so we cannot rebuild them.
    `registry-enrichment.json` declares its source as an external **Google
    Sheet**, i.e. a non-versioned dependency outside AuScope git control.
  - **Three shared filenames have diverged** (`publications-data.json`,
    `stats-data.json`, `data.json` — hers are ~3 days ahead and disagree on
    dataset and sample counts), while her `fair-scores.json` stays frozen at our
    25 Aug copy. **Any naive merge in either direction clobbers one pipeline's
    output.** Her `index.html` is also just a redirect to her DRAFT-watermarked
    `datasets.html`, so our impact overview never appears on her URL — worth
    knowing if that link circulates as "the AuScope tracker".
  - Recommended: converge deliberately — upstream `datasets-data.json`, take her
    registry/software/mapping pages as PRs, and agree who owns each generated
    filename. Note she presented FAIR Implementation Profiles with Lesley Wyborn
    at eResearch 2024; her building *on* the F-UJI scores rather than objecting
    is a useful signal for the public-scores question (§6, §10).

Her page's caveat is also a fair hit on us: it says trends can only be shown by
publication-year cohort "because historical score snapshots are not currently
retained" — confirmed true (`stats-history.json` carries no FAIR fields), see §10.
